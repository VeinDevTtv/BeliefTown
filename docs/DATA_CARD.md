# Data card: BeliefTown synthetic information-patch benchmark

## Contents and provenance

All scenes and labels are procedurally generated by this repository. They contain fictional rooms, NPCs, and parcel observations. There is no personal data, scraped text, game asset extraction, human annotation, or external dataset dependency. Generation and label code is available under MIT, along with the original generated records.

The generator seed is **20261018**. Split-specific seed ranges are disjoint. Each JSONL row contains one complete scene, one target problem, and every labeled patch in that scene's bounded candidate space. Root histories, alternate patches, and counterfactual variants are not split across train and test.

| Split | Scenes | Labeled candidate patches | Feasible candidate patches |
|---|---:|---:|---:|
| Train | 120 | 7,104 | 599 |
| Validation | 24 | 1,372 | 142 |
| Test | 48 | 2,935 | 329 |
| OOD | 24 | 1,590 | 64 |
| **Total** | **216** | **13,001** | **1,134** |

Feasible candidate count is not feasible scene count: several patches from one scene can work. Positive rates are low. Accuracy from an always-infeasible classifier would be misleading, so the release trains BCE scores and evaluates search outcomes/effort rather than promoting class accuracy.

## Scene families

The six balanced families cover missed relocation, delayed reports, repeated-root rumor loops, independent corroboration, conflicting evidence, and information constraints. Some target requests already hold, so the empty patch is optimal. Some requests have no solution within the permitted candidate space. Constrained cases alternate between ordinary and target-protected configurations across family occurrences.

Training, validation, and test scenes have four rooms. OOD scenes have five or six rooms and also change graph density, reliability, and pre-search mobility settings. This is a **bundled distribution shift**, not a causal experiment isolating room count from all other factors.

Priors, travel costs, observations, and requested destinations vary. Procedural actor priors are subjective and are not necessarily equal to the parcel's generating initial distribution. This qualification matters for interpreting Brier scores: they are a belief-quality comparison on these scenes, not a theorem that the configured posterior is globally calibrated.

Only Courier is an active searcher in the procedural benchmark; other actors store and forward evidence. The authored browser demonstration has three active NPCs. Thus the benchmark primarily tests intervention selection for a target character, not emergent multi-agent social behavior.

## Label construction

For each scene, enumerate every permitted delivery subset of size zero through three within the canonical candidate limit of 24. Verify ownership, channels, simultaneous semantics, information constraints, and the resulting target decision. Record all successful alternatives as feasible.

Labels come from the exact reference execution, not an LLM or neural estimate. There is an unavoidable shared-model boundary: both the labels and main verifier assume the same finite-state simulator semantics. Independent belief-path enumeration, route enumeration, and adversarial audit tests provide additional checks, not a separate formal proof of the entire program.

## Integrity and reproducibility

`benchmarks/data/manifest.json` records sizes, class balance, family counts, scene-hash count, and SHA-256 hashes of all split files. The training metadata records its manifest identity. The evaluation records checkpoint hashes. Notebook 04 checks these relationships.

Rebuild the released-size dataset with:

```bash
python -m belieftown dataset --output artifacts/rebuilt-data
```

The command's defaults are the released sizes and generator seed. Rebuilding the whole model/evaluation pipeline can change measured latency with environment and load, even when data and model computation are deterministic.

## Appropriate interpretation

This dataset is a small controlled testbed, not a representative sample of game production. It supports claims about declared evidence models and bounded patch search. It does not measure human believability, player enjoyment, psychological theory of mind, unrestricted natural-language reasoning, or the prevalence of bugs in real games.

Do not choose the published method after repeatedly optimizing against the released test cases and then continue calling that same set untouched. New method development should add new independent held-out seeds or a newly versioned benchmark.
